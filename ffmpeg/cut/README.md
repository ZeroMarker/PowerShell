# 两阶段视频裁剪方案

## 概述

综合两种裁剪方式的优点，将裁剪过程分为两个阶段：

| 阶段 | 工具 | 位置 | 模式 | 速度 | 精度 |
|------|------|------|------|------|------|
| **一、快速粗剪** | `cut.sh` | 服务器（ssh ali） | `-c copy` 流复制 | ⚡ 秒级 | 受关键帧限制 |
| **二、精确细剪** | `cut` (profile) | 本地 Windows | 重新编码 | 🐢 较慢 | ✅ 帧级精确 |

## 阶段一：快速粗剪（服务器）

### 命令

```bash
ssh ali
cd ~/tiktook/
bash cut.sh PRIAN-050.mp4 01:39:26 01:40:10
```

### 实际执行

```bash
ffmpeg -y -ss 01:39:26 -i PRIAN-050.mp4 -to 01:40:10 -c copy -copyts output.mp4
```

### 行为

- `-ss` 在 `-i` 前（input seeking）：跳到起始时间**之前**的最近关键帧
- `-to` + `-copyts`：终点按原始时间戳精确停止
- `-c copy`：流复制，不重新编码

### 输出文件特征

| 项目 | 值 |
|------|-----|
| 首帧 PTS | 5964.066（`01:39:24`，回退到前一个关键帧） |
| 尾帧 PTS | 6010.066（`01:40:10`，**终点精确**） |
| 容器总时长 | **46s**（含开头多出的 2 秒） |
| 播放器显示 | **44s**（从 `01:39:26` 开始播放，跳过开头 2 秒） |
| 时间戳 | 保留原始 PTS（5964~6010） |
| 二次剪辑 | 需用原始时间（`01:39:xx`），不能用相对时间（`00:00:xx`） |

### 优点

- **速度快**：流复制，不编码，大文件秒出
- **终点精确**：`-to + -copyts` 保证结尾精准

### 缺点

- **开头偏移**：最多多出一个 GOP（关键帧间隔），PRIAN-050 多 2 秒
- **PTS 未重置**：二次剪辑需用原始时间

### 下载到本地

```bash
# 在本地 Windows 执行
scp ali:~/tiktook/*.mp4 ~/Downloads/
```

## 阶段二：精确细剪（本地）

### 命令

```powershell
# 在本地 Windows PowerShell 执行
cut .\PRIAN-050_cut_013926-014010.mp4 00:00:02 00:00:46
```

或直接用原始时间：

```powershell
cut .\PRIAN-050_cut_013926-014010.mp4 01:39:26 01:40:10
```

### 实际执行

```powershell
ffmpeg -y -ss 00:00:02 -i input.mp4 -to 00:00:46 `
       -c:v libx264 -crf 23 -preset fast -c:a aac output.mp4
```

### 行为

| 步骤 | 说明 |
|------|------|
| 1. `-ss` 在 `-i` 前 | 跳到起始时间前最近关键帧，快速定位 |
| 2. 解码 | 从关键帧开始解码所有帧 |
| 3. 丢弃 | 丢弃解码后时间戳 < 起始时间的帧 |
| 4. 重新编码 | 从起始时间开始以新 I 帧输出 |

### 输出文件特征

| 项目 | 值 |
|------|-----|
| 首帧 | **I 帧**，PTS = 0 |
| 时长 | **精确 44 秒** |
| 终点 | **精确 `01:40:10`** |
| 画质 | CRF 23（视觉无损） |
| 时间戳 | 从 0 开始 |
| 二次剪辑 | 可直接用相对时间（`00:00:xx`） |

## 完整工作流

```mermaid
graph LR
    A[原始视频<br>4~7GB] --> B[阶段一: 服务器]
    B --> C[快速粗剪<br>9~11MB]
    C --> D[scp 下载到本地]
    D --> E[阶段二: 本地 cut]
    E --> F[精确细剪<br>12~13MB]
```

### 示例：PRIAN-050.mp4

```bash
# 阶段一：服务器上快速粗剪（~5 秒）
ssh ali
cd ~/tiktook
bash cut.sh PRIAN-050.mp4 01:39:26 01:40:10
# 输出: PRIAN-050_cut_013926-014010.mp4 (9.5MB)

# 下载到本地（~1 秒）
# 退出 ssh，在本地执行:
scp ali:~/tiktook/PRIAN-050_cut_013926-014010.mp4 ~/Downloads/

# 阶段二：本地精确细剪（~30 秒，取决于视频长度和 CPU）
cut .\PRIAN-050_cut_013926-014010.mp4 00:00:02 00:00:46
# 或直接用原始时间:
cut .\PRIAN-050_cut_013926-014010.mp4 01:39:26 01:40:10
# 输出: PRIAN-050_cut_013926-014010.mp4 (12.8MB，帧级精确)
```

## 为什么不一步到位？

### 方案 A：服务器直接重编码

服务器 CPU 弱，重编码 4GB 视频极慢，占用服务器资源不划算。

### 方案 B：本地直接 `-c copy` 大文件

本地处理 4~7GB 文件需要同样的磁盘 IO 和带宽，且偏移问题一样存在。

### 方案 C：两阶段（推荐）

| 理由 | 说明 |
|------|------|
| 服务器只做 IO 密集型工作 | 流复制不占 CPU，秒出 |
| 本地只做短文件重编码 | 9~11MB 的小文件，重编码也很快 |
| 带宽友好 | 只下载粗剪后的小文件 |
| 最终精度可控 | 本地重新编码保证帧级精确 |

## 各工具定位

| 工具 | 位置 | 适用 |
|------|------|------|
| `cut.sh` | 服务器 | 快速粗剪大文件，下载到本地 |
| `cut` (profile) | 本地 Windows | 精确细剪、处理已下载的片段 |
| `cut-v1` (profile) | 本地 Windows | 快速粗剪关键帧密集的源文件（如 JAV） |
